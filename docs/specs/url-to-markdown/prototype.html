왜 옮겼나

프런트엔드와 백엔드가 같은 타입을 두 번 선언하고 있었습니다. OpenAPI 스펙을 고치면 클라이언트 코드를 다시 생성해야 했고, 그 사이에 배포된 서비스는 조용히 어긋났습니다. 지난 분기 장애 11건 중 7건(63.6%)이 이 어긋남에서 나왔습니다.

타입은 한 곳에서만 선언되어야 한다. 두 곳에 있으면 둘 중 하나는 거짓말을 한다.

이관 순서

  1. 읽기 전용 엔드포인트부터 옮깁니다. 롤백이 쉽고 트래픽이 큽니다.
  2. 쓰기 엔드포인트는 기능 플래그 뒤에서 shadow 모드로 2주간 비교합니다.
  3. 외부 파트너가 쓰는 공개 API는 마지막까지 REST로 남깁니다.
export const orderRouter = router({
